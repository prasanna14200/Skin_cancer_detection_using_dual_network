## Artifact mismatch and finalization failure

The original CSV SHA256 `2df7edd11a23658e56dc723ee57638476579cb3620d9c5d10039eefa07941fd0` contains epochs 1–24, and paired validation artifacts exist through 24. Epoch 16 is uniquely eligible in the persisted CSV and metric files; its validation loss is `0.08387391282241738`, accuracy `0.8194726166328601`, macro F1 `0.6611314670741572`, MEL recall `63/107`, MEL F1 `0.6028708133971291`, and NV recall `0.9396681749622926`. The original best checkpoint and manifest are absent.

The pinned original runner calls `checked_checkpoint(last_checkpoint.pt)` **before** `checked_checkpoint(best_checkpoint.pt)`, validation-file writes, history CSV write, and epoch console print. If one coherent execution of that code persisted all writes in order, an epoch-24 CSV could not coexist with only an epoch-13 last checkpoint; epoch 16 becoming eligible would also have led to a best-checkpoint write attempt before its CSV row. The observed folder therefore shows a persistence, transfer, or execution-provenance mismatch. Available files do **not** distinguish delayed/non-durable Google Drive writes, an incomplete copy, or another external cause. The exact cause of the last/best checkpoint absence is unresolved; it is not established as an in-memory training or eligibility bug.

A separate finalization defect is established: the original manifest artifact list included `best_checkpoint.pt` whenever in-memory `best_epoch` was set, then tried to hash it without first checking the file existed. The current `train.py` now raises an explicit missing-artifact error before selected-output handling and before manifest hashing. It does not create a surrogate best checkpoint or change eligibility/selection. This source edit changes the current runner hash, so the bounded recovery deliberately uses the exact archived original source for epoch-13 state restoration.

## Deterministic continuation and strict acceptance

The source `restore_resume` restores model, Adamax, scheduler, GradScaler, sampler generator, Python RNG, NumPy RNG, torch CPU RNG, and all CUDA RNG states. `build_components` seeds 42, and `src/train.py` sets cuDNN deterministic mode and disables benchmarking; restoration occurs before the epoch-14 iterator is created. Thus the saved state and source support a faithful **attempt** to continue at 14 on a Tesla T4. They do not alone prove bit-for-bit equivalence: original runtime metadata is missing, and all CUDA/PyTorch operations are not globally forced deterministic. The recovery must pass a strict replay test before its epoch-16 checkpoint is accepted.

The bounded script runs **only epochs 14, 15, and 16**. Before any GPU work it pins and validates the epoch-13 checkpoint, archived source, original CSV, and saved epoch-14/15/16 prediction/metric files. It compares each replayed history row exactly, including train and validation loss, LR, optimizer steps, skips, all saved validation aggregates, and eligibility. It also requires byte-for-byte SHA256 equality of each epoch's validation prediction CSV and metric JSON. Those hashes cover sample IDs, labels, predictions, probabilities, all classwise metrics, confusion matrix, failed gates, and common validation loss. It additionally reports discrete prediction equality, classwise and confusion equality, and numerical differences if a hash fails. A numerically close result is **not** accepted as exact and aborts before later epochs or a selected best is declared. The missing original epoch-16 model checkpoint means its weights cannot be compared byte-for-byte; even an exact observable replay does not prove that missing weight identity.

Each completed recovery epoch writes its own checkpoint plus prediction/metric pair under `experiments/stage15_single_candidate_exp1/recovery_epoch16/`. An eligible epoch-16 best checkpoint is saved there only after its exact replay comparison passes. The script writes a comparison log and a hashed recovery manifest, then stops. It refuses an existing recovery directory, never writes to `run/`, and contains no HAM test or PH2 loader. The recovery output must be downloaded and independently hashed afterward because the original persistence failure mechanism remains unknown.
