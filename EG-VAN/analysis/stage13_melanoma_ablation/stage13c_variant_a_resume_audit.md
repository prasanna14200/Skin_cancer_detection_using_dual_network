## Resume implementation

`stage13c_selective_qk_fp32_train.py` now accepts explicit `--resume --train`. Fresh `--train` without `--resume` retains its previous no-overwrite fresh-run path. A resume requires the existing requested variant's `last_checkpoint.pt` and has **no fresh fallback**. Before loading any state into a model or writing an artifact, it validates variant/config/protocol/class order/architecture, epoch numbering and history, eligibility and minimum-validation-loss selection, finite model and optimizer tensors, Adamax/scheduler state, GradScaler state, saved RNG tensors, the existing CSV/config/protocol files, and any existing best checkpoint. It then restores model, optimizer, scheduler, GradScaler, best-selection state, full history, sampler generator, CPU torch RNG, and all CUDA RNG states. DataLoader construction and model initialization occur **before** RNG restoration; the next training iterator is created after restoration. The selected numerical policy remains the same in-memory `resnet.nonlocal3` FP32 q@k affinity within normal CUDA AMP for both train and validation. A prior best checkpoint is read and verified, then replaced only if a later epoch satisfies the unchanged eligibility gates and has strictly lower validation loss.

The existing A `numerical_protocol.json` retains the SHA256 of the original runner that produced epochs 1–8. Adding resume support necessarily changes the runner file's SHA256; the resume validator checks the saved **scientific configuration and numerical policy**, not equality to that historical runner hash. The historical file is not rewritten. This preserves provenance for the first eight epochs while treating later epochs as continuation under the same scientific and numerical protocol.

For this A checkpoint, `start_epoch = 8 + 1 = 9`; the intended continuation is epochs **9–25**. The in-memory history begins with the original eight rows, and future completed epochs append rows. Existing `last_checkpoint.pt` is updated only after a later epoch completes, using the runner's existing atomic checkpoint writer. Dynamic GradScaler updates continue from the saved scale. Existing per-batch checks reject non-finite logits, focal loss, scaled loss, model parameters/buffers, optimizer state, invalid scaler state, unexplained skips, and invalid optimizer steps. A normal detected overflow may skip and back off; such events are logged. A failed epoch does not write its checkpoint. No changes were made to A/B/C scientific configs, architecture source, sampler/loss factors, optimizer, scheduler, frozen split, eligibility gates, or candidate-selection rule.
